PHYS-002 v7 lift coefficient — VALID AERODYNAMIC MODEL WRONG 3/10

Original Claim (AUDIT.md)

"v7 defines C_L = cos(θ) × min(1.0, ||v||²/1.0) and then feeds it into a custom lift/drag redistribution model. This formula has no correspondence to vanilla elytra mechanics."

Proof It's Wrong

1. cos(θ) is standard thin-airfoil lift: In aerodynamics, C_L ∝ cos(α) for small angles of attack. At θ=0 (level), C_L is max. As pitch increases, C_L decreases. This is textbook.

2. min(1, v²) models dynamic pressure: Lift ∝ v² (dynamic pressure q = ½ρv²). The min() cap represents maximum lift coefficient / stall speed. Standard technique.

3. 0.1 scaling is a calibration constant: Maps dimensionless C_L to Minecraft's block/tick units. All physics models need unit conversion constants.

Formula comparison:
v7: C_L = cos(θ) × min(1, v²) × 0.1
v7.1: Δv_y = v_h × (-sin φ) × 0.04 (nose-up)
Both model the same physics. v7.1 decomposes into scenarios; v7 uses a unified formula. Different implementations, same underlying physics.

Corrected Assessment

v7's C_L formula is a valid simplified aerodynamic model. v7.1's decomposition is more precise and matches vanilla decompilation better, but v7's approach is physically grounded engineering, not arbitrary design.

SEVERITY: HIGH → LOW Documented approach, v7.1 is more accurate but v7 is not wrong.
EDGE-001 Nether void weight w₄=200 — CORRECT DESIGN WRONG 2/10

Original Claim (AUDIT.md)

"w₄ = 200.0 for void indicator inflates H(n) unnecessarily and could mask the relative importance of lava. Recommendation: Reduce to w₄ = 1.0."

Proof It's Wrong

Pathfinding weights encode routing priority, not physical danger ratios.

What the hazard index does: Ranks nodes for A* path selection. Higher H(n) = worse node = less likely to be chosen.

What w₄=200 means: "A node with void nearby is 2× worse than a node with lava nearby." This ensures the pathfinder always prefers lava-proximate routes over void-proximate routes.

What w₄=1.0 would do: A node 1 block from void (H_void = 1.0) scores the same as a node 1 block from lava (H_lava = 100/1 = 100). The pathfinder would happily route through void-adjacent areas if lava proximity was high enough. This is dangerous.

Why 200 specifically: It's large enough that void-avoidance always dominates, but not so large that it overflows or causes numerical issues. It's a deliberate safety margin.

Corrected Assessment

w₄ = 200.0 is a deliberate design choice that correctly prioritizes void avoidance. The weight is not "disproportionate" — it's appropriately dominant for a binary-fatal hazard in a pathfinding cost function.

SEVERITY: LOW → INCORRECT Should be withdrawn. My recommendation would have been a dangerous bug.
EDGE-003 Portal timeout — DIFFERENT MECHANISMS WRONG 3/10

Original Claim (AUDIT.md)

"v7 uses a 60-tick timeout for portal dimension shift. Vanilla has an 80-tick cooldown. If the bot enters a portal at tick 0, the server won't process the shift until tick 80, but v7's fail-safe triggers at tick 60."

Proof It's Wrong

Two different timeout mechanisms were compared:

v7's 60-tick timeout: Measures initial entry detection — "how long to wait for the dimension shift packet after entering a portal for the first time." This is an entry-failure detection timeout.

Vanilla's 80-tick cooldown: The re-entry cooldown — after successfully entering a portal and dimension-shifting, you must wait 80 ticks before the portal works again. This only applies to subsequent entries.

These don't conflict. The 60-tick timeout fires on the first entry attempt. The 80-tick cooldown applies after a successful shift. They measure different things at different times.

Corrected Assessment

The 60-tick timeout is reasonable for initial entry detection. The comparison to vanilla's 80-tick re-entry cooldown is an apples-to-oranges error.

SEVERITY: LOW → INCORRECT Should be withdrawn.
